Taller práctico guiado de aplicaciones web reactivas con Angular

Construcción paso a paso de PharmaCore Enterprise con Signals, Standalone Components, Control Flow y Formularios Reactivos

Objetivos y contexto del taller

En esta sesión práctica guiada construiremos paso a paso una Single Page Application (SPA) empresarial para la gestión y monitoreo reactivo de medicamentos y suministros médicos: PharmaCore Enterprise.

A lo largo del taller implementaremos los pilares del desarrollo frontend moderno en Angular 22:

  • Arquitectura Standalone: Aplicaciones desacopladas sin módulos intermedios (NgModule), simplificando el árbol de dependencias.
  • Reactividad con Signals: Manejo de estado síncrono, predecible y de alto rendimiento mediante primitivas reactivas (signal, computed).
  • Control Flow Nativo: Estructuración de plantillas con las directivas @for (con seguimiento estricto track), @switch / @case y @empty.
  • Formularios Fuertemente Tipados: Validación reactiva estricta con FormBuilder.nonNullable y Validators.
  • Enrutamiento SPA con Carga Perezosa: División de código en tiempo de ejecución (code splitting) con loadComponent: () => import(...).

Hoja de ruta de construcción incremental

La aplicación se construirá de forma secuencial a través de Vertical Slices (micro-pasos funcionales). Cada paso agrega una funcionalidad completa que puede ser explicada, probada y visualizada de inmediato:

  1. Slice 1: Creación del proyecto, modelo de dominio tipado (Product), servicio reactivo base con signal() y primer renderizado visual en vivo (primeros 15-20 minutos).
  2. Slice 2: Mutaciones inmutables (updateStock, deleteProduct), enlace de eventos y experimento de reactividad en memoria.
  3. Slice 3: Señales computadas automáticas (computed), grafo reactivo y componente de métricas HeaderComponent.
  4. Slice 4: Desacoplamiento modular del catálogo (ProductListComponent) con badges condicionales mediante @switch y manejo de estado vacío con @empty.
  5. Slice 5: Formulario reactivo fuertemente tipado (ProductFormComponent) con validación síncrona, control de errores accesible y alta de medicamentos.
  6. Slice 6: Enrutamiento SPA con carga perezosa (app.routes.ts) y ensamblaje final en el layout raíz.
  7. Slice 7: Reto activo en sala (“Tu Turno”: Filtro de búsqueda en tiempo real con Signals) y checklist de autoverificación.

Paso 1.3. Modelado del dominio tipado con la interfaz Product

Definiremos el contrato de datos estricto para los medicamentos y equipos farmacéuticos. Este modelo tipado garantiza inmutabilidad en tiempo de compilación y previene el uso indebido del tipo any.

Crea la carpeta de modelos e implementa la interfaz en src/app/models/product.model.ts:

mkdir -p src/app/models

Crea el archivo src/app/models/product.model.ts:

export type ProductCategory = 'ANTIBIOTICOS' | 'ANALGESICOS' | 'EQUIPO_MEDICO' | 'CUIDADO_PERSONAL';

export interface Product {
  readonly id: number;
  readonly name: string;
  readonly description: string;
  readonly price: number;
  readonly stock: number;
  readonly category: ProductCategory;
  readonly isActive: boolean;
}

export type CreateProductDTO = Omit<Product, 'id' | 'isActive'>;

Justificación técnica del modelo

  • ProductCategory: Unión discriminada de cadenas literales que restringe las categorías a un conjunto cerrado válido para el negocio.
  • readonly: Modificador de TypeScript que protege cada propiedad contra mutaciones accidentales fuera del flujo reactivo del servicio.
  • CreateProductDTO: Utiliza el tipo utilitario Omit para definir el contrato de creación de productos, excluyendo el identificador (id) y el estado interno (isActive), los cuales son asignados automáticamente por el sistema.

Paso 1.4. Servicio centralizado con Signals mediante ProductService

Los Signals son contenedores reactivos de valores síncronos que notifican automáticamente a los consumidores (vistas o señales derivadas) cuando su contenido cambia.

Genera el servicio con el CLI de Angular:

Fase 2. Mutaciones de estado y buenas prácticas de inmutabilidad (Slice 2)

Paso 2.1. Implementación de mutaciones seguras en el servicio

Para modificar el estado contenido en un Signal de forma predecible, se utiliza el método .update(), el cual recibe una función transformadora que toma el valor actual y retorna una nueva referencia inmutable.

Abre src/app/services/product.ts y agrega los métodos de actualización de existencias y eliminación:

  public updateStock(id: number, delta: number): void {
    this.productsSignal.update(currentList =>
      currentList.map(item => {
        if (item.id === id) {
          const newStock = Math.max(0, item.stock + delta);
          return { ...item, stock: newStock };
        }
        return item;
      })
    );
  }

  public deleteProduct(id: number): void {
    this.productsSignal.update(currentList =>
      currentList.filter(item => item.id !== id)
    );
  }

Principios de inmutabilidad aplicados

  • currentList.map(...): Crea un nuevo arreglo sin alterar el arreglo original. Para el producto modificado, genera un nuevo objeto usando el operador spread ({ ...item, stock: newStock }).
  • Math.max(0, item.stock + delta): Regla de negocio que previene que las existencias caigan por debajo de cero unidades.
  • currentList.filter(...): Retorna un nuevo arreglo que excluye el ítem con el id seleccionado, preservando la inmutabilidad de la colección.

Paso 2.3. Experimento guiado sobre inmutabilidad en Signals

¿Por qué es indispensable usar funciones inmutables (.map, .filter, { ...item }) al actualizar Signals en lugar de modificar propiedades de objetos directamente?

Realizaremos un experimento modificando intencionalmente el código para observar el fallo de reactividad:

  1. Abre src/app/services/product.ts y reemplaza temporalmente el método updateStock por una mutación directa por referencia:
  // CÓDIGO TEMPORAL DE EXPERIMENTO (MUTACIÓN DIRECTA)
  public updateStock(id: number, delta: number): void {
    const list = this.productsSignal();
    const item = list.find(p => p.id === id);
    if (item) {
      (item as any).stock += delta; // Mutación directa en memoria
    }
  }
  1. Guarda el archivo y ve al navegador. Haz clic repetidamente en el botón +1.
    • Resultado observable: El número en pantalla NO cambia.
  2. Explicación técnica: El motor de detección de cambios de Angular compara la referencia del arreglo anterior con la nueva utilizando Object.is. Dado que mutamos la propiedad interna de un objeto dentro del mismo arreglo, la referencia en memoria del arreglo sigue siendo exactamente la misma. Por lo tanto, el Signal considera que no hubo cambio y omite la actualización del DOM.
  3. Restauración: Restaura el método updateStock original con this.productsSignal.update(...) para devolver el comportamiento reactivo correcto.

Fase 3. Métricas derivadas con Signals computados y Header empresarial (Slice 3)

Paso 3.1. Señales computadas reactivas con computed

En aplicaciones reales necesitamos valores derivados del estado primario (por ejemplo: conteo de existencias críticas, valor monetario total del inventario).

En lugar de calcular estos valores manualmente en cada evento o mantener variables adicionales sincronizadas, Angular provee computed():

  • Reactividad automática: Se recalculan únicamente cuando alguno de los Signals leídos en su función interna produce un nuevo valor.
  • Memoización (Caching): Si el valor derivado se consulta múltiples veces pero sus dependencias no han cambiado, Angular retorna el valor memorizado sin reejecutar el cálculo.
  • Solo lectura: Los Signals computados son inherentemente inmutables; no tienen método .set() ni .update().

      price: 14.00,

      category: 'ANALGESICOS',
      isActive: true
    },
    {

      name: 'Tensiómetro Digital de Brazo',
      description: 'Monitor de presión arterial automático de alta precisión.',
      price: 110.00,
      stock: 12,
      category: 'EQUIPO_MEDICO',
      isActive: true
    },
    {
      id: 4,
      name: 'Alcohol Antiséptico 70% 1L',
      description: 'Solución desinfectante para uso hospitalario y tópico.',
      price: 8.50,
      stock: 0,
      category: 'CUIDADO_PERSONAL',
      isActive: true
    }
  ]);

  public readonly products = this.productsSignal.asReadonly();

  public readonly totalProducts = computed(() => this.productsSignal().length);

  public readonly totalInventoryValue = computed(() =>
    this.productsSignal()
      .filter(p => p.isActive)
      .reduce((accum, item) => accum + (item.price * item.stock), 0)
  );

  public readonly lowStockCount = computed(() =>
    this.productsSignal().filter(p => p.stock > 0 && p.stock < 5).length
  );

    this.productsSignal().filter(p => p.stock === 0).length
  );

import { Component, inject } from '@angular/core';
import { FormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { Router, RouterLink } from '@angular/router';
import { ProductService } from '../../services/product';
import { ProductCategory } from '../../models/product.model';

@Component({
  selector: 'app-product-form',
  imports: [ReactiveFormsModule, RouterLink],
  templateUrl: './product-form.html',
  styleUrl: './product-form.css'
})
export class ProductForm {
  private readonly fb = inject(FormBuilder);
  private readonly productService = inject(ProductService);
  private readonly router = inject(Router);

  protected readonly categories: ProductCategory[] = [
    'ANTIBIOTICOS',
    'ANALGESICOS',
    'EQUIPO_MEDICO',
    'CUIDADO_PERSONAL'
  ];

  protected readonly productForm = this.fb.nonNullable.group({
    name: ['', [Validators.required, Validators.minLength(4), Validators.maxLength(80)]],
    description: ['', [Validators.required, Validators.minLength(10), Validators.maxLength(250)]],
    price: [0, [Validators.required, Validators.min(0.5)]],
    stock: [0, [Validators.required, Validators.min(0)]],
    category: ['ANALGESICOS' as ProductCategory, [Validators.required]]
  });

  protected isSubmitted = false;

  protected onSubmit(): void {
    this.isSubmitted = true;

    if (this.productForm.invalid) {
      this.productForm.markAllAsTouched();
      return;
    }

    const formValues = this.productForm.getRawValue();

    this.productService.addProduct({
      name: formValues.name,
      description: formValues.description,
      price: Number(formValues.price),
      stock: Number(formValues.stock),
      category: formValues.category
    });

    this.router.navigate(['/catalog']);
  }
}

Justificación de las utilidades reactivas

  • fb.nonNullable.group({...}): Crea un formulario fuertemente tipado donde los valores nunca retornan null al invocar reset(), sino su valor inicial.
  • Validators: Reglas síncronas que validan longitud de cadenas (minLength, maxLength) y cotas numéricas (min).
  • markAllAsTouched(): Marca recursivamente todos los controles como interactuados (touched), forzando el despliegue visual de los mensajes de validación si el usuario intenta enviar el formulario incompleto.
  • productForm.getRawValue(): Extrae un objeto JavaScript con el tipado estricto inferido del formulario.

Fase 7. Reto activo formativo y autoverificación técnica (Slice 7)

Reto formativo en sala para filtrado reactivo de búsqueda con computed

En src/app/components/product-list/product-list.ts, implementa una barra de búsqueda para filtrar medicamentos en tiempo real a medida que el usuario escribe, sin modificar el estado original en ProductService.

Requerimientos técnicos del reto

  1. Declarar un Writable Signal local searchQuery = signal<string>('').
  2. Declarar un Signal computado filteredProducts = computed(...) que filtre productService.products() por coincidencias en name o description (insensible a mayúsculas/minúsculas).
  3. Añadir en product-list.html un campo <input type="text"> que actualice searchQuery en el evento (input).
  4. Iterar sobre filteredProducts() en la directiva @for.
Ver solución sugerida del reto

En src/app/components/product-list/product-list.ts:

import { Component, inject, signal, computed } from '@angular/core';
import { CurrencyPipe } from '@angular/common';
import { ProductService } from '../../services/product';
import { Product } from '../../models/product.model';

@Component({
  selector: 'app-product-list',
  imports: [CurrencyPipe],
  templateUrl: './product-list.html',
  styleUrl: './product-list.css'
})
export class ProductList {
  protected readonly productService = inject(ProductService);

  protected readonly searchQuery = signal<string>('');

  protected readonly filteredProducts = computed(() => {
    const q = this.searchQuery().toLowerCase().trim();
    return this.productService.products().filter(p =>
      p.name.toLowerCase().includes(q) || p.description.toLowerCase().includes(q)
    );
  });

  protected onIncreaseStock(product: Product): void {
    this.productService.updateStock(product.id, 1);
  }

  protected onDecreaseStock(product: Product): void {
    this.productService.updateStock(product.id, -1);
  }

  protected onDeleteProduct(id: number): void {
    if (confirm('¿Está seguro de eliminar este medicamento del inventario?')) {
      this.productService.deleteProduct(id);
    }
  }
}
